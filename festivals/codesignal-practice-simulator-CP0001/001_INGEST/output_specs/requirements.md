# Requirements: CodeSignal Practice Simulator

## Priority Definitions

- **P0:** Required for the repository to provide a trustworthy, reusable
  simulator and complete the approved migration.
- **P1:** Required to make repeated practice and agent collaboration practical
  after the P0 lifecycle is working.
- **P2:** Deliberately deferred extension work that must not delay the first
  `file_storage` simulator.

## P0 — Candidate Session Lifecycle

| ID | Requirement | Acceptance Criteria | Source / Rationale |
| --- | --- | --- | --- |
| R05 | Support `start`, `resume`, `status`, `time`, `task`, `test`, and `submit` through one documented command-line interface, with human-readable and `--json` output. | Each command has deterministic argument resolution, documented exit codes, error messages, and integration tests. `python -m` behavior matches the installed console command. | Existing Just recipes map to the desired commands. |
| R06 | Provide authentic full mode and accelerated drill mode. | Full mode always stores a 90-minute limit. Drill mode stores a named shortened profile and its explicit duration. Both store start/deadline timestamps from an injected UTC clock and expose remaining time. | Existing 90-minute default; approved drill requirement. |
| R07 | Create isolated, self-contained attempt workspaces. | Starting one attempt copies only files from a validated local fetch cache; no candidate edit, test artifact, status artifact, or session event leaks into another attempt or the cache. Workspace creation is transactional: injected directory, copy, state, pointer, flush, and replace failures roll back only the newly created staging workspace and leave no partial attempt or active pointer. A transaction-owned attempt marker makes publish-before-pointer interruption reconciliation delete only the newly owned unpublished attempt while preserving the former pointer and attempts. If setup has not produced a valid cache, `start` returns a clear setup-required error and creates no attempt. Runtime attempts and the cache are ignored by Git. | `scripts/new_attempt.py:COPIED_FILES`. |
| R07a | Execute assessment scoring in an environment isolated from project and reference modules. | Each scoring child launches exactly as `<absolute-interpreter> -I -S <attempt>/.scoring/run_group.py <group>` with the selected attempt as `cwd`. Its attempt-local bootstrap admits only copied attempt candidate/test paths plus interpreter standard-library paths, with no global/user site, project, editable-install, solution, study, reference, cache, or environment-derived import path; its minimal environment omits `PYTHONPATH` and Python site/configuration variables. Tests prove installed editable-project, `PYTHONPATH`, and loose-reference sentinels cannot import or influence candidate results. | Candidate assessment integrity requires process-level import isolation. |
| R08 | Persist authoritative session state and append-only events. | Each attempt owns validated `session.json` and `events.jsonl`; state updates are atomic, events contain schema/version, UTC timestamp, event name, command outcome, and attempt ID; readers tolerate a trailing incomplete JSONL line after interruption. | Existing static `attempt.json` and ephemeral score output are insufficient. |
| R09 | Enforce an explicit lifecycle. | Only active attempts can be resumed or tested. `status` and `time` observe and persist expiry, then return an expired view. `submit` may finalize active or expired attempts; once submitted it is idempotent and returns the stored result without a new score, event, or revision. Rejected transitions leave state intact and produce useful errors. A lock prevents concurrent command writers. | Current submit does not close attempts. |

## P1 — Agent-Safe Collaboration and Learning

| ID | Requirement | Acceptance Criteria | Source / Rationale |
| --- | --- | --- | --- |
| R10 | Generate a concise, agent-readable `STATUS.md` and expose `context` in Markdown and JSON. | Views derive only from state/events and contain safe paths, selected assessment/mode, clock, lifecycle, score summary, and next legal commands. Markdown is never parsed as state. | Existing `ATTEMPT.md` and `RESULT.md` are static/submission-only. |
| R11 | Provide an updateable `COACHING.md` surface separate from candidate code. | The file is non-executable, never imported or scored, has a clear candidate-approval boundary, and can be updated without a simulator command touching `simulation.py`. Tests demonstrate that coaching changes do not change scores. | Existing guidance is dispersed across `notes/` and `study/`. |
| R12 | Provide `AGENTS.md` guidance for live sessions. | It instructs agents to read status/context first; to update only coaching unless candidate assistance is explicitly requested; to never expose reference solutions during a timed attempt; and to preserve state/event integrity. | No agent guidance exists in the source project. |
| R13 | Retain instructional material without letting it compromise assessment realism. | Walkthrough, staged solutions, and study checks remain outside candidate attempt workspaces; docs explain when these materials may be read. The Level-4 visible-test/spec conflict remains explicit. | `notes/walkthrough.md`, `solution/stages/`, and discrepancy note. |
